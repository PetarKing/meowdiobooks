# Decisions with workflow consequences

| Problem and credible options | Decision | Evidence and trade-off |
| --- | --- | --- |
| Voice audition comparison required a separate “Approve Audition N” action after choosing. Leaving the second action preserves the old flow; applying on selection shortens it. | Clicking an audition card selects its exact revision immediately in the draft. A single Play/Stop control handles listening independently. **New voice** switches to the existing voice-creation controls; generating still requires its explicit action. Cast-stage acceptance remains separate and authoritative. | Cast interaction fixtures and focused tests verify revision selection, playback, New voice/Back and stage acceptance. An accidental card choice is reversible by choosing another audition before accepting Cast. |
| Cast and Voices need the same visual grid, but Cast opens identity review while Voices also needs playback. Separate card designs had drifted; a single clickable Voice tile would conflate inspect and play. | Both steps render the same `CastRosterCard` composition and status accent: a horizontal spine, curved divider, and tinted monogram field on desktop, and a two-column bowl and underline on phones. Cast opens identity review from its card. Voices opens review from the text and plays or stops from the initials field. The cue disappears and a waveform replaces the initials while audio plays; clicking again or reaching the end restores them. The divider draws on hover or keyboard focus; playback animates the field, ink bloom, and curve. Reduced motion stops it. | Shared desktop/phone light/dark renders, 61-member/long-name checks, actual play/stop and natural-end checks, focus and reduced-motion checks show one design across both steps without losing separate actions. Phone bowl cards keep the selection grid while using less total height than a single-column horizontal list. |
| Accepted Review “Change settings” returned to a sparse manual Scan CTA. Always showing the CTA is explicit; automatically scanning removes a redundant step. | That intentional return launches the existing nonpublishing Review candidate scan once and shows in-page progress. Initial entry still exposes an explicit Scan action. Failure leaves Retry; no accepted review is replaced until ordinary acceptance. | App return/failure tests and the existing `process_review(... publish=False)` backend boundary. This spends local processing upon a clear editing action; no new provider route or publication authority is added. |
| Cast’s three native confirmations bypassed the product dialog and had inconsistent focus. An accepted Cast was then copied into the editor even though backend edits require a candidate, and it opened Cast when the common next task was voice review. | Use `DialogSurface` with explicit cancel/continue actions and focus restoration. Confirming replacement automatically prepares an editable candidate and opens Voices; Edit cast remains available there. A saved newer draft opens directly. | Browser keyboard/Escape, direct Voices return, edit navigation, failure recovery and backend rebase checks. Preparing a candidate may perform local processing; the accepted Cast remains active until replacement acceptance. |
| The fixed-color decoration could contaminate custom host palettes or distract from content. | Mark custom semantic `PresentationRoot` palettes and show the new canopy only in the canonical studio. It sits behind content and moves by a few pixels; reduced-motion stops it. | Eight rendered mode/width/motion checks verify decoded art, no overflow and palette isolation. The image adds about 300 KB to the canonical style package. |
| Export showed a book description but had no way to save one. A display-only field would misrepresent the audiobook and Library record; making it required would break existing callers and older saved exports. | Export offers an editable description initialized to “Generated by Meowdiobooks.” The optional, 2,000-character request field is saved with each Library export and written to M4B or MP3 chapter metadata. Omission remains `null` for legacy callers; an explicitly cleared field remains empty. Changing books resets the editor to that book’s defaults. | API and package tests check JSON/multipart requests, legacy records, blank values, escaped metadata, and tags read back from real M4B/MP3 output. The field adds persisted metadata without changing audio generation or existing export requests. |

## September 29 finish boundaries

- Library failure is separate from an empty library. Retry reuses `listLibrary`; a refresh retains the last successful list. Replacing it with an empty/skeleton state would misrepresent available editions. Two App regressions and independent Studio failure/retry checks cover this boundary.
- A first voice audition starts directly; replacement of an existing audition set retains a designed confirmation. Production regeneration replaces the set (backend regression `test_app_v2_finish.py`), so the creation view no longer promises preservation. The synthetic gateway now mirrors that replacement and leaves the accepted snapshot intact. Candidate availability is distinct from already generated audio and saved Library exports.
- Working-stage artwork uses layered background images rather than an isolated parent or pseudo-element. This contains the artwork without horizontal overflow and lets fixed dialog overlays cover sticky navigation. Phone scroll, hit-testing and keyboard checks caught and verified this seam.
