# Independent Cast check

`frontend/scripts/verify-cast-independent.mjs` exercised the real UI against the in-memory studio gateway at 1440px and 390px, light and dark. [The report](report.json) contains the four results. Screenshots include the [desktop roster](roster-1440-light.png), [phone roster](roster-390-dark.png), [long name](long-name-390-light.png), [applied audition](audition-applied-390-dark.png), [Ghost editor](ghost-1440-light.png), and [populated settings editor](accepted-settings-390-dark.png).

Observed: the 61-voice roster remains a grid (five columns on desktop, two on phone), long names wrap without clipping or horizontal overflow, clicking Audition 1 changes the applied choice immediately without closing the inspector, and Ghost swaps to a populated voice editor. Back restores the audition choices. Canceling a replacement audition preserves all three earlier candidates. Accepted Cast → Change settings opens the populated editor directly; there is no repeat scan button. Replacement, reclassification, and audition-regeneration confirmations are app dialogs. Escape/cancel restores trigger focus, and the inspector restores its tile focus. No native dialogs, runtime errors, or `/api/` requests occurred.

The first independent run exposed a focus-return bug in Cast confirmations. The Cast agent removed the conflicting `autoFocus` from the cancel button; this final matrix reran all four states successfully. One-click audition choice updates the working Cast selection; final Cast acceptance remains the point where the workflow persists it. This audit uses synthetic fixtures and does not exercise a real provider or book.
