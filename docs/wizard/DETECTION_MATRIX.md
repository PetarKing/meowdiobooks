# Detection and issue-handling matrix

This is the authoritative inventory of what v2 detects, what evidence it shows, what a user decision
means, and how that decision reaches audio. “Blocking” means the next phase cannot be accepted.

| Issue / status | Detection and evidence | Severity | False-positive / false-negative risk | User actions | Downstream consequence | Required proof |
|---|---|---|---|---|---|---|
| Empty extracted page / implemented | Empty source block, page image and adjacent pages | Blocking until reviewed | Blank illustration pages are false positives; image-only text is a false negative without OCR | Confirm intentional blank; rerun Extract | Confirmed blank remains source-covered and silent; rerun invalidates Dialogue onward | Intentional blank test; image-only fixture; Alice blank-page case |
| Source-coverage recovery / implemented | Exact block ranges reconstructed from Dialogue spans; gap/overlap/invented-block evidence | Blocking recovery state, not a content warning | Low FP because byte ranges are mechanical; cannot detect content absent from Extraction | Rebuild Dialogue; try another Extraction only when source is wrong | Successful Extraction remains accepted; no Review revision publishes until exact coverage is restored | Gap, overlap, altered source, recovery UI and stale-revision tests |
| Suspicious extraction / implemented | Replacement characters, spaced-letter corruption and anchored extractor warnings with exact range | Warning | Typography can resemble corruption; clean-looking OCR can still be wrong | Keep, narrate, exclude, rerun Extraction | Narrate changes ownership; exclude becomes a source-linked omission; rerun creates a complete new Extraction revision | Positive and clean negatives; upstream-rerun and executed render-policy tests |
| Reading order / partial evidence | Extractor-supplied layout/column warnings plus page preview | Warning when evidence exists | Current extractors do not emit reliable coordinates for every multi-column PDF | Accept order; rerun Extraction | Rerun invalidates Dialogue onward | Extractor evidence contract; multi-column real fixture remains required |
| Chapter boundary / implemented | Explicit chapter/part/book/act/prologue/epilogue and configured structured headings anchored to a range; TOC-like pages suppressed | Warning requiring a decision | Ornamental headings can overmatch; implicit starts can be missed | Chapter starts here; not a boundary | Every Dialogue span receives exactly one reviewed chapter ID | Public-domain headings, TOC negative, mid-page ownership tests |
| Repeated matter / implemented | Same normalized first/last page-edge line on multiple pages, grouped by identical text | Warning | Repeated refrains near page edges can overmatch; varying headers can be missed | Keep; exclude | Exclude splits narration and becomes an explicit recording-script omission | Header/footer positive, repeated-body negative, evidence-scoped bulk-token and render tests |
| Page number / implemented | Roman/Arabic number-shaped page-edge line | Warning | Numeric prose at an edge can overmatch | Keep; exclude | Same as repeated matter | Edge positive and body negative |
| Web address / implemented | Exact inline range beginning with `http://`, `https://`, or `www.`; terminal sentence punctuation excluded | Warning | Bare domains and addresses split across lines are intentionally missed; unusual punctuation can be ambiguous | Keep; exclude | Exclude removes only the anchored address; a narrower address policy overrides a broader enclosing warning | Standalone/inline positives, bare-domain negative, punctuation boundary, nested-footnote policy and action-matrix tests |
| Footnote / implemented | Exact footnote-shaped anchors; explicit Translation/TL Note sections extend an anchor across wrapped lines and a proved unfinished adjacent-page continuation | Warning | Numbered dialogue can overmatch; unmarked notes can be missed; uncertain isolated markers stay line-scoped | Keep; narrate; exclude | Narrate/exclude executes on the complete anchored note ranges; source remains inspectable | Wrapped-line and adjacent-page positives, chapter/list and abandoned-section negatives, action matrix and source-range execution tests |
| Front/back matter / implemented | Copyright, contents, translator/editorial and similar anchored headings | Warning | Story text can use the same words; unmarked peripheral text can be missed | Keep; narrate; exclude | Narrate/exclude executes on render spans; source remains inspectable | Keyword positives, prose negatives and source-range execution tests |
| Built-in Dialogue format / implemented | Label + brackets/quotes, conservative label + spaced dash, uppercase label + colon line, opt-in screenplay, and unlabelled curly/straight/guillemet/CJK quotes; per-regex counts/examples | Blocking only on overlap | Quotes may be thoughts/citations; unusual/nested conventions can be missed. Screenplay is opt-in because headings resemble cues | Toggle successful regexes; add unrestricted local raw regex; rerun preview | Enabled matches create source-anchored spans; disabled matches remain preview evidence | Subaru/Alice characterization, radio-play labels, multilingual formats, prose negatives |
| Same-rule interrupted turn / implemented | A new bundled labelled start before the outer closer, or a complete custom-regex match concretely inside itself; exact competing speaker/text outcomes | Blocking until chosen | Bundled start grammar is conservative; arbitrary regex-language recursion is not inferred | Split into turns; keep together; leave as narration; change rule | Selected source-exact partition is recorded per occurrence | Dangling-quote fixture, custom recursive concrete match, three actions and exact reconstruction |
| Clean cross-block/page continuation / implemented | Asymmetric labelled bracket/curly delimiters, no competing start before closer, capped at eight blocks/6,000 characters | Automatic structural link | Straight quotes and ambiguous/new-start cases are intentionally not linked; closer beyond the cap is missed | No decision for clean cases; ambiguous material stays unjoined or enters interrupted-turn review | One logical turn retains exact per-block fragments | Cross-page fixtures, straight-quote negative and exact reconstruction |
| Regex overlap / implemented | Both match/profile IDs and the concrete overlapping source range, for built-in or custom rules | Blocking until chosen | Mechanical overlap is exact; equivalent labelled/unlabelled matches are coalesced first; theoretical language intersection is not attempted | Choose either interpretation; leave as narration; disable/refine a rule | Choice is scoped to that profile pair’s overlaps and persists across unrelated toggles | Conflict/coalescing, narration, persistence and acceptance-gate tests |
| Configured open speaker / implemented | Literal and regex-configured markers such as `???` or `Unidentified Voice` | Warning / AI target | A label can be semantically unknown without matching configured syntax | Fill gaps with AI; narrator fallback; change marker configuration | Any configured marker echoed by AI normalizes to `?` and narrator fallback | Configurable marker and public-domain proof |
| Unlabelled quoted speech / implemented | Source-anchored quote range plus neighboring context; no speaker invented | Warning / AI target | Thought, citation or speech ambiguity remains semantic | Focused AI attribution; narrator fallback; change regex and rerun | Qwen returns one speaker or `?` for each selected target; unresolved turns use the narrator | Alice quote fixture, focused-row validation, unresolved path |
| Qwen attribution / implemented | One target per prompt with no model-facing ID; broad conversational context for open labels and tight sentence context for unlabelled quotes; a base name or `/` decision is checked again locally against the byte-identical prompt | Warning when unresolved; unrelated disagreement withholds the decision; an exhausted mechanical retry aborts | Correlated local checks can agree incorrectly; conservative fuzzy name collation can combine distinct similar names; distant evidence can remain outside the bounded window; literal support does not prove semantic correctness | Accept reviewed result; inspect AI checks; keep narrator fallback; change regex/strategy and rerun | A name publishes on normalized agreement or conservative whole-token/edit/fuzzy equivalence plus literal support for both answers; `/` becomes surrounding narration only when both checks agree; base `?` or a configured unknown skips verification; only a complete revision publishes | Selective-call, equivalent-name/disagreement, slash-verification, independent retry, configured-marker and cross-page correction tests |
| Alias/identity relationship / implemented | One focused label, 2–4 contextual examples, and up to eight loosely similar candidate labels with evidence | Flagged identity blocks auditions | Plot-dependent aliases can remain unknowable; fuzzy suggestions can be wrong | Confirm the primary label and aliases; keep separate | Every accepted spelling maps to one durable character ID; mapping conflicts fail | Shortlist validation, deterministic relationship symmetry and conflict tests |
| Unknown/editorial/collective label / implemented | Dossier-grounded category proposal (`unresolved-marker`, `editorial`, `group`, `character`) | Flagged identity blocks auditions | A descriptive label can later reveal a named person | Confirm category/name or keep unresolved | Character/group needs an accepted voice; editorial/open marker does not become a character | Category validation and exact voice gate |
| Joint delivery / implemented | Accepted group identity with a dedicated voice or confirmed layered `voiceRoute`; exact connector-name matches are suggestions only | Blocking if a route or effective member voice is missing | `&`, `/` and “and” do not prove simultaneous members | Keep a dedicated group voice; confirm suggested members; select existing characters manually | Confirmed members synthesize separately and mix into one timeline event, never sequentially | Route acceptance, live mixed preview, render-plan and mixed-track metadata/audio tests; real joint listening remains required |
| Voice readiness / implemented | Narrator and characters require exact accepted audition revisions; groups require one dedicated revision or a confirmed layered route | Blocking | A playable preview can still be a poor artistic fit | Generate/regenerate and select one exact revision; or confirm a group route | Cast cannot publish until every dedicated voice and layered member reference is ready | Missing/stale audition, invalid route and full-cast gate tests |
| Enrichment workload/output / backend-only preview | Backend contracts can plan bounded chapter/scene windows and validate state/range decorators; the current UI only skips this phase | Optional and unavailable in the current UI | Decorators remain unproved on representative chapters | Continue without enrichment | Cannot alter text/speaker/identity; current TTS does not consume decorators | Ownership, budget, invalid row and skip tests; product enablement remains future work |
| Final recording script / implemented | Source-complete script assembled from accepted Dialogue, Review, Cast and Enrichment revisions when Generate first needs it | Generated automatically; blocked only by missing accepted inputs | Dialogue missed upstream cannot be recovered here | Return to the owning phase, correct it and accept a new revision | One cached faithful script; exact upstream revisions determine freshness; unresolved dialogue keeps narrator fallback | Coverage, blocker, cache, invalidation and render-plan tests |
| Generation failure / implemented | Job progress/error, staging receipt and prior current revision | Job failure; prior audio stays playable | A successful file does not prove artistic quality | Retry or change accepted inputs | Pointer changes only after complete chapter metadata/WAV validation | Cleanup and atomic pointer tests |
| Stale audio / implemented | Each chapter’s pinned Dialogue/Review/Cast/Enrichment/recording-script revisions compared with active revisions | Notice, never destructive | None mechanically; listening quality is separate | Play old revision; regenerate; export only current | Old WAV/segments remain inspectable; stale reasons are explicit; M4B rejects stale inputs | Stale/current history, playback and export tests |

## Honest remaining limits

- Image-only and complex multi-column PDFs still need a proved OCR/layout recovery path.
- Attribution and aliases can remain unresolved when evidence is absent; `?` is correct, not failure.
- Full chapters can require substantial local compute. Alice’s 10-page characterization produced 105
  render events; the UI must present workload honestly.
- Punctuation alone never establishes joint membership. Exact-name matches may be suggested, but a
  layered route is authoritative only after user confirmation.
